# 첫 CFG 구현 범위

Date: 2026-09-30

## 배경

화면 인식(OCR) 기능을 위해 캡처 영역 좌표를 저장할 곳이 필요해졌다. `DESKTOP_PET_BEHAVIOR_SPEC.md` 6장이 이미 CFG 계약(스키마 버전, 캐릭터 ID, 표시 크기, 항상 위, 모드, 위치)을 정의해뒀고, `TODO.md`에도 "CFG 저장/복원"이 남은 항목으로 있었다. 캡처 영역 하나만을 위한 좁은 저장소를 새로 만들기보다, 이참에 BEHAVIOR_SPEC이 정의한 계약대로 첫 CFG를 제대로 만들기로 했다.

## 결정

### 스키마는 전체를, 구현은 실제로 바뀌는 값만

`PetSettings`에 BEHAVIOR_SPEC 표의 모든 필드(`SchemaVersion`, `CharacterId`, `DisplaySizeDip`, `AlwaysOnTop`, `Mode`, `WindowLeft`/`WindowTop`)와 이번에 추가한 `CaptureRegion`을 전부 포함시켰다.

다만 실제로 로드·저장 로직을 연결한 건 `Mode`와 창 위치뿐이다. `DisplaySizeDip`, `AlwaysOnTop`, `CharacterId`는 아직 사용자가 바꿀 수 있는 UI가 없어서 기본값만 저장되고, `CaptureRegion`은 화면 인식 기능(다음 단계)에서 채울 자리만 마련해뒀다.

이유: 스키마를 나중에 확장하면서 매번 파일 형식을 마이그레이션하는 것보다, 처음부터 전체 계약을 파일에 반영해두고 구현만 점진적으로 채우는 편이 더 단순하다.

### "변경을 모아 순차 저장"은 지금 규모에서 생략

BEHAVIOR_SPEC은 "변경을 모아 순차 저장"을 요구하지만, 지금 저장이 일어나는 지점은 드래그 종료와 모드 변경 클릭뿐이라 이산적이고 드물다. 배치(batch) 큐 없이 `lock`으로 동시 저장만 직렬화하는 것으로 충분하다고 판단했다.

화면 인식 기능에서 캡처 영역을 자주 바꾸거나, 설정 화면에서 슬라이더 같은 연속 입력이 CFG에 매 프레임 반영되기 시작하면 이 판단을 재검토해야 한다.

### 모니터 검증은 정밀하지 않음

저장된 창 위치가 화면 밖인지 판단할 때, 모니터별 정밀 DPI 변환 대신 `System.Windows.Forms.SystemInformation.VirtualScreen`(전체 가상 화면 범위)을 주 모니터 DPI로 근사 변환해서 검사한다. 서로 다른 DPI의 모니터가 섞인 환경에서는 부정확할 수 있지만, 화면 밖으로 완전히 벗어난 경우를 걸러내는 안전장치로는 충분하다고 판단했다.

## 영향

- `Services/PetSettingsStore.cs` 신설. `%AppData%\DesktopPet\settings.json`에 저장.
- `MainWindow`가 시작 시 CFG를 읽어 모드/위치를 복원하고, 드래그 종료·모드 변경 시 저장한다.
- 다음으로 화면 인식 기능을 만들 때 `CaptureRegion` 필드를 실제로 읽고 쓰게 된다.
